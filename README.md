# EXIT CODE

중학교 마이크로비트 코딩 미션 웹사이트입니다. GitHub Pages가 화면을 제공하고 Apps Script가 로그인, 제출 검수, Google Sheets 저장을 처리합니다. 미션의 예시 내용은 이전에 논의한 비밀번호, 행운의 암호, 3번의 기회, 5초 제한, A → B → A를 바탕으로 구성했습니다.

## 로컬 체험

이 폴더에서 `python -m http.server 8765 --bind 127.0.0.1`을 실행하고 브라우저에서 `http://127.0.0.1:8765/`을 엽니다. `config.js`의 URL이 빈 상태에서는 학생과 코딩 도우미 모두 **체험 시작**으로 들어갈 수 있습니다. 같은 브라우저에서 두 모드를 오가며 제출과 승인을 확인할 수 있습니다. 체험 기록은 해당 브라우저에 저장됩니다.

## Google Sheets 연결

1. 기존 시트를 사용한다면 **사본에서 먼저 확인**합니다. 아래 열 이름과 실제 시트의 첫 행을 비교하고, 의미가 같은 기존 열은 백업 후 표준 이름으로 맞춥니다. 기존 Apps Script도 사본을 보관합니다.
2. 대상 스프레드시트의 **확장 프로그램 → Apps Script**에서 이 프로젝트의 전체 `Code.gs`를 붙여 넣습니다. 편집기에서 `setup`을 한 번 실행하고 권한을 부여합니다. 시트를 새로고침하면 **EXIT CODE** 메뉴가 표시됩니다.
3. `학생명단`에 학생ID, 반, 번호, 이름, 역할을 입력합니다. 학생ID는 전체에서 고유해야 합니다. 반과 번호는 숫자, 역할은 `학생`을 사용합니다. 도우미는 **EXIT CODE → 도우미 계정 등록·재설정**에서 담당 반과 계정을 설정합니다. 기존 도우미의 비밀번호 검증 형식이 다르면 같은 ID로 새 비밀번호를 설정합니다.
4. **배포 → 새 배포 → 웹 앱**에서 실행 사용자는 배포자, 액세스는 Google 로그인 없이 학생이 접속할 수 있는 **모든 사용자**로 설정합니다. 학교 계정 정책에 해당 옵션이 없다면 익명 접속이 허용되는 배포 환경이 필요합니다. Sheets 파일 자체의 공유 권한은 담당 교직원으로 관리합니다.
5. 배포에서 발급된 `https://script.google.com/macros/s/…/exec` 주소를 `config.js`의 빈 문자열에 넣습니다. 이후 Apps Script를 수정할 때는 배포 관리에서 **새 버전**으로 기존 배포를 업데이트합니다.

학생 인증은 반·번호·이름의 일치 여부를 사용합니다. 다른 학생이 이 정보를 알고 있다면 그 계정으로 로그인할 수 있으므로 실제 명단을 연결하기 전에 학교의 인증 방식과 개인정보 기준을 확인합니다. 도우미 비밀번호는 계정별 솔트와 Apps Script 속성에 저장된 비밀 키로 HMAC 검증합니다. 세션은 최대 4시간이며 Google 캐시에서 먼저 만료될 수 있습니다.

[Google Apps Script 웹 앱 배포](https://developers.google.com/apps-script/guides/web)

### 시트와 기존 데이터

| 시트 | 사용 데이터 |
| --- | --- |
| 학생명단 | 학생ID, 반, 번호, 이름, 역할 |
| 도우미계정 | 계정ID, 담당 반, 권한, 솔트, 비밀번호해시 |
| 미션정보 | 미션번호, 미션제목, 난이도, 문제, 성공조건, 힌트1, 힌트2, 필요블록, 이미지, 사용여부 |
| 미션진행 | 학생ID, 미션번호, 시작시간, 최종활동시간, 진행상태 |
| 미션제출 | 제출ID, 학생ID, 미션번호, MakeCode URL, 제출시간, 검수상태, 검수자, 검수시간, 최종수정시간, 최종수정자, 이전제출ID, 검수이력JSON |
| 검수이력 | 이력ID, 제출ID, 처리종류, 이전상태, 변경상태, 처리자, 처리시간 |
| 간식지급 | 기존 미션별 지급 기록 보관 |
| 차수간식이력 | 학생ID, 지급차수, 지급상태, 처리시간, 처리자 |

- 초기 설정은 부족한 열을 오른쪽에 추가합니다. 기존 지급 기록은 `간식지급`에서 대조하고, 운영자가 새 차수에 대응한다고 확인한 건만 `차수간식이력`에 수동으로 옮깁니다. 상태는 `paid` 또는 `cancelled`이며 같은 학생·차수의 마지막 행이 현재 상태입니다. 실물 지급 여부가 불명확한 기존 학생은 지급 전에 기존 기록을 확인합니다.
- 기존 제출은 학생ID로 연결하고 제출ID, 미션번호, 검수상태를 읽습니다. 기존 시트에 다른 열 이름이나 상태 값이 있다면 사본에서 대조한 다음 매핑을 조정합니다.
- 예시 미션은 비어 있는 `미션정보`에 추가됩니다. 수업 문제와 힌트는 시트 편집 권한이 있는 담당자가 수정하고 미션번호 1~5는 각 한 행씩 유지합니다. `사용여부`는 TRUE/FALSE를 사용합니다.
- 승인 취소는 후속 미션에 시작 또는 제출 기록이 생기기 전까지 가능합니다. 해당 간식이 지급된 경우 먼저 지급을 취소합니다.

## GitHub Pages 배포

1. GitHub 저장소에 `index.html`, `style.css`, `app.js`, `model.js`, `config.js`, `.nojekyll`, `assets/`를 올립니다. `Code.gs`와 이 문서도 소스 관리에 포함할 수 있습니다.
2. **Settings → Pages → Deploy from a branch**에서 `main`과 `/(root)`를 선택하고 저장합니다.
3. Pages에 표시된 HTTPS 주소를 열어 실제 계정으로 확인합니다. 저장소에는 학생명단, 도우미 비밀번호, Apps Script 속성 값을 넣지 않습니다.

[GitHub Pages 배포 브랜치 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 배포 확인

- 가상 계정 두 개와 가상 학생을 넣은 사본에서 학생 로그인·도우미 로그인을 확인합니다.
- 미션 1~3의 상태가 도전 전, 4~5가 잠김인지 확인합니다. 힌트 1 이후 힌트 2가 열리는지, MakeCode 공유 링크의 형식이 검증되는지 확인합니다.
- 학생이 제출하면 도우미가 검수 대기 항목을 확인합니다. 재도전 후 재제출하고, 1~3 승인 이후 4, 4 승인 이후 5가 열리는지 확인합니다. 새로고침과 재로그인 후 기록을 대조합니다.
- 같은 반 도우미 두 명이 같은 제출을 검수해 한 건만 반영되는지 확인합니다. 다른 반 도우미 화면에 학생이 표시되지 않는지, 번호·미션·검수·최근 제출 정렬과 선택 상태가 맞는지 확인합니다.
- 지급 가능 상태에서 지급, 지급 취소, 재지급을 확인합니다. 도우미 두 명이 동시에 지급 처리했을 때 한 건만 기록되는지 확인합니다.
- 연결 오류가 발생하면 `config.js`의 `/exec` 주소, 웹 앱 배포 버전과 권한, 시트 이름과 첫 행, Apps Script 실행 로그를 확인합니다.
